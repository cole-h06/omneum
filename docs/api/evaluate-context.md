
# Evaluate Context

`evaluate_context` evaluates observations and returns source reliability, claim support, conflicts, and source-dependency estimates.

## Evaluate Observations

Use `OmneumClient.evaluate_context()` with a sequence of `Observation` objects and a `DependencyEstimatorConfig`. The example uses the local `omneum-server` installation.

```python
import asyncio

from mcp import StdioServerParameters
from omneum import (
    Claim,
    DependencyEstimatorConfig,
    Observation,
    OmneumClientConfig,
    Source,
    open_stdio_client,
)

async def main():
    observations = [
        Observation(
            observation_id="source-a",
            source=Source(
                kind="web_document",
                identifier="https://example.com/report-a",
            ),
            claim=Claim(
                entity_namespace="company",
                entity="acme",
                attribute="revenue",
                value=42_000_000,
            ),
        ),
        Observation(
            observation_id="source-b",
            source=Source(
                kind="web_document",
                identifier="https://example.com/report-b",
            ),
            claim=Claim(
                entity_namespace="company",
                entity="acme",
                attribute="revenue",
                value=42_000_000,
            ),
        ),
    ]

    estimator = DependencyEstimatorConfig(
        upstream_weight=0.25,
        citation_weight=0.20,
        assertion_lineage_weight=0.20,
        ownership_weight=0.10,
        temporal_weight=0.10,
        graph_weight=0.15,
        temporal_window_seconds=7200.0,
    )

    config = OmneumClientConfig.from_local_deployment()
    server = StdioServerParameters(command="omneum-server")

    async with open_stdio_client(config, server) as client:
        evaluation = await client.evaluate_context(
            observations,
            estimator=estimator,
        )

        for claim in evaluation.claim_support:
            print(claim.support)
            print(claim.estimated_independent_support_count)
            print(claim.conflicting_claims)

asyncio.run(main())
```

`from_local_deployment()` reads the configuration generated by `omneum install` or `omneum init`.

## Evaluate Mapped Records

Use `evaluate_mapped()` for application records already supported by a `ContextMapper`.

```python
evaluation = await client.evaluate_mapped(
    records,
    mapper,
    estimator=estimator,
)
```

The mapper supplies source identity, claim fields, observation IDs, and available provenance. The SDK uses the same evaluation path as `evaluate_context()`.

See [ContextMapper](../context_mapper.md).

## Source Equivalence

Declare `ExactEquivalence` only for source references containing identical evidence across the evaluated claims.

```python
from omneum import ExactEquivalence, SourceReference

evaluation = await client.evaluate_context(
    observations,
    estimator=estimator,
    exact_equivalences=(
        ExactEquivalence(
            SourceReference(
                "web_document",
                "https://example.com/original",
            ),
            SourceReference(
                "web_document",
                "https://example.com/exact-copy",
            ),
        ),
    ),
)
```

Both references must occur in `observations`. The evaluator rejects inconsistent claim profiles or component dependencies.

`exact_equivalences` defaults to an empty sequence. Provenance does not automatically create exact-equivalence declarations.

## Evaluation Results

`evaluate_context()` returns `ContextEvaluation`.

```python
for source in evaluation.source_reliability:
    print(source.source, source.reliability)

for claim in evaluation.claim_support:
    print(claim.claim, claim.support)
    print(claim.supporting_source_count)
    print(claim.estimated_independent_support_count)

    for source in claim.supporting_sources:
        print(source.source, source.contribution)

    for conflict in claim.conflicting_claims:
        print(conflict.claim, conflict.support)

for dependency in evaluation.pairwise_dependencies:
    print(dependency)
```

| Field | Type |
| --- | --- |
| `source_reliability` | `tuple[SourceEvaluation, ...]` |
| `claim_support` | `tuple[ClaimSupportResult, ...]` |
| `pairwise_dependencies` | `tuple[PairwiseDependencyResult, ...]` |
| `convergence` | `ConvergenceMetadata` |
| `evaluation_latency_ms` | `float \| None` |

Each `ClaimSupportResult` includes `support`, `agreement_weight`, `supporting_source_count`, `estimated_independent_support_count`, `dependency_signal_coverage`, `supporting_sources`, and `conflicting_claims`.

## MCP Tool

The SDK calls `evaluate_context` through `omneum/transport/mcp.py`. The MCP request uses `EvaluateAssertionRequest`, defined in `omneum/models.py`.

```json
{
  "protocol_version": "v1",
  "deployment_id": "urn:uuid:01234567-89ab-cdef-0123-456789abcdef",
  "voprf_key_version": 1,
  "voprf_mode": "voprf",
  "voprf_ciphersuite": "ristretto255-SHA512",
  "linkage_encoding_version": 1,
  "assertions": [
    {
      "source_id": "<opaque linkage token>",
      "attribute_id": "<opaque linkage token>",
      "claim_id": "<opaque linkage token>"
    }
  ],
  "source_pairs": []
}
```

Use deployment metadata returned by `ping`. Generate linkage tokens through the SDK; the placeholders are not valid request values.

### Assertions

`assertions` contains source–attribute–claim edges.

| Field | Type |
| --- | --- |
| `source_id` | `str` |
| `attribute_id` | `str` |
| `claim_id` | `str` |

Assertions must be unique and sorted by `(source_id, attribute_id, claim_id)`.

### Source Pairs

`source_pairs` contains every unordered pair of distinct sources.

```json
{
  "source_a_id": "<opaque linkage token>",
  "source_b_id": "<opaque linkage token>",
  "dependency": 0.0,
  "weighted_signal_coverage": 1.0,
  "exact_equivalence": false
}
```

`dependency` and `weighted_signal_coverage` must be finite values in `[0, 1]`. `exact_equivalence` defaults to `false`.

For `n` sources, submit exactly `n * (n - 1) // 2` pairs, sorted by `(source_a_id, source_b_id)`, with `source_a_id < source_b_id`.

The SDK builds this matrix from the observation provenance. Direct MCP callers must supply it.

## MCP Response

The MCP handler returns `CallToolResult` containing `structuredContent` and JSON text content.

The structured payload uses `EvaluateAssertionResponse` from `omneum/models.py`.

```text
EvaluateAssertionResponse
├── protocol_version
├── deployment_id
├── voprf_key_version
├── voprf_mode
├── voprf_ciphersuite
├── linkage_encoding_version
├── summary
├── source_reliability[]
│   ├── source_id
│   └── reliability
├── claim_support[]
│   ├── attribute_id
│   ├── claim_id
│   ├── support
│   ├── agreement_weight
│   ├── is_attribute_max_support
│   ├── supporting_source_count
│   ├── estimated_independent_support_count
│   ├── dependency_signal_coverage
│   ├── supporting_sources[]
│   └── conflicting_claims[]
└── metadata
```

The SDK maps the opaque response identifiers back to application-level `Source` and `Claim` objects.

## Validation

Limits are enforced by `omneum/tools/evaluate_context.py`.

| Resource | Maximum |
| --- | ---: |
| Assertions | 4,096 |
| Sources | 64 |
| Attributes | 2,048 |
| Claims | 4,096 |
| Source pairs | 2,016 |
| Conflicting-claim entries | 16,384 |

Duplicate assertions, missing source pairs, invalid linkage tokens, noncanonical ordering, and inconsistent equivalence declarations are rejected.

## Errors

MCP application errors set `isError=true` and return `message` and `omneum_code` in `structuredContent`.

```json
{
  "message": "The assertion graph is invalid.",
  "omneum_code": "invalid_graph"
}
```

Python SDK failures use `ContextEvaluationRejectedError`, `ContextEvaluationResponseError`, or `ContextEvaluationTransportError`. Mapping failures use `ContextEvaluationMappingError`.

See [Errors](errors.md) for the error codes and exception handling.
