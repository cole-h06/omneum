# Local and hosted security audit — 2026-10-10

The local MCP server, SQLite Context Graph, Rust evaluator, and hosted Network bootstrap were traced through implementation and tests. Confirmed defects were fixed. This is not a production launch approval: production Network pins remain unprovisioned, and the Kubernetes/edge deployment has not been exercised on a live cluster.

The working tree already contained substantial user changes. The audit preserved those changes and did not read deployment credentials, publish artifacts, or contact production services. PostgreSQL databases and Compose volumes used here were disposable and removed afterward.

## Remaining risks and release prerequisites

1. **Hosted production is not provisioned.** `omneum/contribution/network.py:83` deliberately contains no production pins. Provision and independently verify the production domain, separate Network key, public pin/version and consent/credential authority before enabling it. This is a launch blocker for the public Network feature.
2. **Deployment-level admission and network isolation remain external requirements.** Authentication queries run before principal quotas (`omneum/transport/network.py:98`); unauthenticated traffic can consume the bounded 64 request slots. The Helm chart does not supply NetworkPolicy or edge/IP limits (`deploy/helm/omneum-network/templates/deployment.yaml:17`). Compose evaluator containers also have ordinary container networking (`compose.yaml:63`). Verify edge connection/header/TLS limits, database access restrictions, and evaluator egress policy on the actual platform. Kubernetes runtime enforcement was not tested here.
3. **Authorized VOPRF access is intentionally an evaluation oracle.** The daemon cannot determine the purpose/plaintext of a blinded element (`src/daemon/mod.rs:395`). An authorized malicious client can evaluate guessed inputs and consume the shared rate budget; pseudonymous Network tokens are susceptible to dictionary/linkage analysis by authorized evaluators. Never reuse the scalar for signing or other protocols. Ingestion validates token structure, not cryptographic issuance or report truth (`omneum/ingestion/postgres.py:1`). No signing-oracle command or private-key export was found.
4. **Explicit consent is session/configuration-wide, not per-call human approval.** Once opted in, new observations supplied by any client trusted to use the contributor session can be contributed (`omneum/contributor.py:144`). A malicious tool client cannot select arbitrary export paths or upload graph history through these tools, but the MCP host must control who can use an enabled contributor session. Network graph structure, source kinds, scores, parent counts, ownership equality and time deltas remain sensitive pseudonymous metadata (`omneum/contribution/builder.py:71`). Account/IP attribution is also visible to the hosted service. Consent does not provide anonymity.
5. **Local storage is plaintext and the owning UID is trusted.** Claims, identifiers, retrieval fields and metadata are stored locally in cleartext (`omneum/storage/sqlite.py:285`). Disk encryption, backups and cloud-sync settings remain operating-system responsibilities. A process running as the owning UID, or root, can read/modify the graph and bypass application checks. Schema validation does not authenticate rows, prevent rollback of database snapshots, or protect against same-UID pathname replacement between validation and SQLite open (`omneum/storage/sqlite.py:145`). No disk/history quota or bounded history loading exists (`omneum/storage/sqlite.py:323`); a trusted SDK caller can exhaust disk or memory.
6. **Locality checks have limits.** Known remote mounts are rejected, but unavailable Linux mount metadata and unknown filesystem types are not proof of locality (`omneum/storage/filesystem.py:84`, `omneum/storage/filesystem.py:138`). A local APFS directory synchronized by another application remains a local filesystem. Avoid synchronized graph directories when data must remain on one machine. Caller-selected PostgreSQL storage/evaluators/metrics recorders are explicit integrations whose behavior is outside the default SQLite privacy guarantee.
7. **Windows storage does not establish equivalent isolation.** POSIX owner/mode checks are conditional (`omneum/storage/sqlite.py:127`, `omneum/storage/sqlite.py:229`); no Windows DACL/owner validation is implemented. Protected evaluator serving supports Linux/macOS only (`src/bin/omneumd.rs:15`). Do not claim Windows protected deployment readiness based on portable path tests.
8. **Key rotation, retention and backup are operator procedures.** Exclusive provision refuses overwrite; one daemon holds one key for its lifetime (`src/daemon/mod.rs:152`, `src/daemon/mod.rs:170`). Rotation must coordinate a fresh scalar, public pin, version and retained graph identities; version relabeling is not rotation. Admission budgets grow until operator pruning (`omneum/network_operator.py:173`). Startup role validation is not a complete allowlist of every direct PostgreSQL GRANT; migrations and actual effective privileges still require operator review (`migrations/production_002_ingestion.sql:46`, `migrations/production_006_credentials.sql:37`).

## Verification performed

- Local boundary suite: **290 passed, 3 skipped**. Covered SQLite filesystem/concurrency/privacy, daemon IPC, MCP framing/tools, contribution projection and hosted ASGI boundaries. The three skips were platform/optional integration checks; hosted database checks were exercised separately.
- Final SQLite/schema/ACL/migration/concurrency suite: **76 passed**, including the final schema-prefix bypass and replaced-ledger regressions. The native ACL/schema/subtype subset also passed independently (**28 passed**). Counts overlap the larger boundary suite; they are not a combined total.
- Real disposable PostgreSQL + HTTPS/bootstrap/operator suite: **113 passed**. Included consent revocation, authorization, idempotency, quotas, startup role escalation/membership/ownership checks and mounted DSN CLI behavior.
- Rust production-feature library suite: **15 passed**, including RFC vector, peer credentials, rate/authorization tests and crypto property tests.
- Fresh isolated Compose build and smoke: **passed** with actual HTTPS, proof verification, verified PostgreSQL TLS, ingestion and retry persistence. Cross-UID probe denied private-key reads, `/proc/1/mem`, and evaluator IPC. Containers and test volumes were removed.
- Repository production Linux isolation harness: **passed** in a disposable network-disabled Linux container, including key/directory/binary/config/memory/ptrace denial, authorized IPC, unrelated UID denial, malformed owner/modes, restart/shutdown and openat2 ENOSYS fallback.
- Helm lint/render, Compose configuration validation and `git diff --check`: **passed**. No live Kubernetes cluster, macOS launchd service installation, production credentials or production database was used. Native macOS ACL and peer-credential behavior was exercised on this workstation; same-UID fixture daemons alone do not establish service UID separation.
